
## Product SEO Optimization — Slug-based Routing

**Problem:** Product detail pages used UUID-based URLs (`/products/{uuid}`) and the products catalog opened products in a client-side modal instead of navigating to dedicated server-rendered pages. This was bad for SEO — search engines couldn't index individual product pages properly.

**Changes made:**
1. Created `lib/slug.ts` — slug utility with `slugify()`, `buildProductSlug()`, and `isUUID()` functions
2. Created `app/products/[slug]/page.tsx` — new slug-based product detail route (replaces `[id]` route)
   - Handles both slug-based URLs (e.g. `/products/ai-resume-builder`) and old UUID URLs (backward compat)
   - Added `generateStaticParams()` for build-time pre-rendering
   - Enhanced `generateMetadata()` with richer keywords, product meta tags
   - JSON-LD structured data: `SoftwareApplication` + `BreadcrumbList` schemas
3. Deleted `app/products/[id]/` — old UUID-based route
4. Updated `components/public/products-catalog.tsx` — replaced modal with `<Link>` to `/products/{slug}`
   - Removed modal, `window.history.replaceState`, `ProductGallery` client component
   - Added `useProductSlugs()` hook for consistent slug generation
   - Product cards now show short descriptions for better SEO content
5. Updated `app/products/page.tsx` — added JSON-LD `ItemList` schema for the catalog page
6. Updated `app/sitemap.ts` — product URLs now use slugs instead of UUIDs
7. Created `supabase/migrations/20261113000000_add_product_slug.sql` — optional slug column

**Key design decision:** Slugs are generated at runtime from product names (no DB dependency required). The `[slug]` route fetches all active products and matches by slugified name. Old UUID URLs still work via `isUUID()` check.

## Admin Product SEO Controls

**Problem:** Admin product edit form had no SEO fields — couldn't control meta title, description, keywords, or URL slug per product.

**Changes:**
1. Added `slug`, `seo_title`, `seo_description`, `seo_keywords` fields to `Product` type in `lib/supabase/types.ts`
2. Updated SQL migration `20261113000000_add_product_slug.sql` to add `seo_title`, `seo_description`, `seo_keywords` columns
3. Updated `app/products/[slug]/page.tsx`:
   - Added `resolveSlug()` helper — uses admin slug if set, falls back to auto-generated
   - `getProductBySlug()` now checks DB `slug` column first, then auto-generated slug
   - `generateMetadata()` uses admin-provided seo_title/seo_description/seo_keywords when available
   - `generateStaticParams()` uses `resolveSlug()`
4. Updated `components/public/products-catalog.tsx` — `useProductSlugs()` checks `product.slug` first
5. Updated `app/products/page.tsx` — query includes SEO columns, JSON-LD uses admin slug
6. Updated `app/sitemap.ts` — fetches slug column, uses admin slug when available
7. Updated `components/admin/products-manager.tsx`:
   - Added SEO fields to `defaultForm` and `startEdit()`
   - SEO fields saved in `saveRow()` payload (with fallback deletion on error)
   - New SEO section in the form UI with:
     - URL Slug input (with live `/products/` prefix display)
     - SEO Meta Title (with character count, max 70)
     - SEO Meta Description (with character count, max 170)
     - SEO Keywords (comma-separated)
     - Google Search Preview (live preview of how the page will appear in Google)
   - "View" button in table now links to actual product page using slug
   - Excel export includes SEO columns

**Key design:** All SEO fields are optional — if admin leaves them empty, the app auto-generates values from product name, category, description, and features.

## Bulk SEO for 120 Products + Deployment (later same day)

**SQL scripts** (all run successfully by user in Supabase SQL Editor):
- `supabase/scripts/seo-all-products-part1.sql` (products 1-60)
- `supabase/scripts/seo-all-products-part2.sql` (products 61-120)
- `supabase/scripts/seo-fix-duplicate-taskflow.sql` (fixes one duplicate slug)
- `supabase/scripts/seo-audit.sql` (read-only verification tool)
- Migration `20261113000000_add_product_slug.sql` must be run FIRST (adds the SEO columns); running scripts before it gives `column "seo_title" does not exist`.

**Critical build blocker found:** `components/admin/products-manager.tsx` line ~462 had literal `"` in JSX text → ESLint `react/no-unescaped-entities` is an ERROR, so every Vercel build failed and Vercel kept serving the last good (old) deployment. Fixed with `&quot;`. This is why the live site ignored admin SEO fields for so long. Lesson: always check `npx eslint app components lib --quiet` before pushing; `tsc` alone does not catch build-blocking lint errors.

**Data audit (verified via Supabase REST):** 120 active products, 0 missing slug/title/description/keywords, 0 duplicate slugs (after TaskFlow fix), 120 unique titles, 0 malformed slugs, 0 titles >70 chars. Two TaskFlow API products were matched by the same ILIKE pattern → same slug; fixed by exact-ID updates (Flask → `taskflow-flask-rest-api-jwt`, FastAPI/React → `taskflow-fastapi-react-task-manager`).

**Code hardening added:**
- Legacy/UUID/auto-generated slugs resolve via a `legacyMap` fallback and 308-redirect to the canonical admin slug (`permanentRedirect`). Note: because generateMetadata runs first, Next.js emits a client-side meta-refresh 308 rather than a true HTTP 308 — canonical tag still correct.
- `trimDescription()` truncates meta descriptions at a word boundary with an ellipsis (65 descriptions exceeded 160 chars).

**Repo hygiene:** two local `sss` commits had accidentally added ~1.2 GB of `.next-verify*` build caches (largest blob 418 MB > GitHub's 100 MB limit, making pushes impossible). Cleaned with `git reset --mixed origin/main` (non-destructive, commits remain in reflog), restored build-mutated `next-env.d.ts`/`tsconfig.json`, and added `.next-verify*/` to `.gitignore`.

**Verified live (after redeploy):** product pages show admin SEO titles/descriptions/canonicals; `/products` links and `sitemap.xml` contain all 120 admin slugs.

That domain is served by **LiteSpeed (separate legacy host)** and returns 404 for product slug pages, while the real app is on `https://weconnectinovativesolutions.vercel.app` (Vercel). So all canonical tags + sitemap URLs currently point to URLs that 404. Awaiting user decision on which domain should be canonical.
