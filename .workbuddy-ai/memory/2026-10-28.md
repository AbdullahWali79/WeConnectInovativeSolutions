## Accounts Manager: restored the password gate + mobile optimisation

**File:** `components/admin/accounts-manager/accounts-manager.tsx` (only file touched)

### Why the password prompt disappeared
The lock was not broken — the whole component was **rewritten** in commit `a02e5add "Build accounts renewal and follow-up workspace"`, which dropped the gate. Confirmed with `git log -S"Abdullah123" -- <file>`: the string last existed in `d2077d0c`, and `git show <commit>:<file> | grep -c Abdullah123` returns 0 for `2314f7f0`, `c2b73717`, `3308545d` and the working copy. The rewrite also added the renewal workspace, subscriptions and followups.

### Restored gate
- State: `unlocked`, `password`, `unlockError`.
- Password remains `Abdullah123@` (client-side only — real protection is the admin role + RLS, this is a "shoulder-surfing" gate for a page holding client credentials).
- Gate renders **before** the main return but **after every hook** (verified: last hook is the `useEffect` on `unlocked`; no hooks between the gate and the return).
- Reused the navy/gold decorated design: `bg-primary` header band, glass lock badge, gold accent line, ambient glows, `wc-input` with key icon, animated inline error (no `alert()`), `autoFocus`, `aria-invalid`, `role="alert"`.
- **Behaviour change:** data is no longer fetched until unlocked — `useEffect` now runs `if (unlocked) loadData()` with `[unlocked]` deps, so credentials never load before the password is entered. This also means the page starts in `loading` state only after unlock.
