# Prompt library

## Excel bulk import and export

Admin can add individual prompts with **Add prompt**, or use **Excel import & export** on `/admin/prompts`. Approved contributors have the same template/import controls on `/prompts/contribute` and can export only their own prompts. Admin export includes all prompts, including unpublished and paid template text; share the empty template when collecting submissions.

Download the `.xlsx` template and fill the **Prompts** sheet (one prompt per row). The **Instructions** and **Example (do not import)** sheets explain the format and are ignored on import. There are separate columns for six Google Drive preview URLs. Use `0` for free prompts; paid prompts require a price; an HTTPS purchase link is optional.

For an existing Google Form, download its response spreadsheet as `.xlsx`, upload it, and select the response worksheet (for example **Form Responses 1**). The importer suggests matches for common question headings. Use **Match your form columns** to map custom questions, including Urdu headings, then **Validate & preview rows**. First-row headings are required. Timestamp, email, and other unmapped columns are ignored; imports do not create contributor accounts from form responses. An unmapped price defaults to free. One mapped Drive column can contain comma/newline-separated links, with a maximum of six links per prompt. Existing prompt text and variables are preserved literally.

Select the completed workbook to validate and preview up to 100 rows (2 MB maximum file size). All rows must be valid before importing; errors show Excel row numbers. Formula cells and duplicate title/template pairs within a file are rejected. Very large prompt text requires smaller batches. Exports use the same columns and can be imported again, but importing creates **new prompts**, not updates; reimporting a workbook creates copies. Split exports containing more than 100 prompts before importing.

Admin chooses pending review or immediate publication. Contributor imports derive ownership and status from their verified session, applying the existing direct-publishing permission. Every batch is validated again on the server and saved in one atomic insert. No database migration is needed for Excel support.

Tests: `node --test scripts/test-prompts.cjs scripts/test-prompts-excel.cjs` covers workbook round trips, invalid rows, safe text cells, limits, and server-action approval/ownership behavior with mocked database access.

Apply `supabase/migrations/20260905000000_prompt_library.sql` to the same Supabase project before deploying. The existing Supabase URL and service role environment variables are used only on the server. No changes to course accounts, enrollments, auth triggers or existing tables are required.

- `/prompts`: public search, category and pricing filters, newest/title sorting, Drive previews, variable generation and copying.
- `/prompts/contribute`: separate email/password registration and access request, login, submission and editing, approval status and admin notes.
- `/admin/prompts`: existing main-admin authentication; contributor permissions, review, editing, creation and unpublishing.

Contributors and hashed sessions live exclusively in `prompt_contributors` and `prompt_sessions`. Passwords use salted scrypt; session cookies are HttpOnly, SameSite=Lax and Secure in production. Session tokens are stored as SHA-256 digests and expire after seven days. Auth and submissions use persistent atomic 15-minute attempt limits. All four module tables use RLS with no browser grants; server actions enforce ownership and admin authorization. No Supabase Auth user/student profile is created. This initial contributor portal does not include email verification or self-service password recovery.

An approved contributor can submit prompts for review. Direct publishing is a separate admin option. Editing a published prompt returns it to pending unless direct publishing is enabled. Revoking contributor access stops future submissions; previously published content is moderated separately. Admin notes are private.

Templates use `{{BusinessName}}`, `{{TargetAudience}}`, etc. Variables are inferred from the actual template; values are substituted literally (including `$` sequences) without recursive substitution. Generation is local template filling, with no AI calls. Preview files are supplied by contributors, not generated by the website.

Paid prompts use PKR prices and an optional external HTTPS purchase/contact link. When no link is supplied, the public page shows that the purchase link has not been added. Their template bodies are excluded from public database queries. Payment and delivery occur externally; there is no on-site checkout, purchase verification or unlock flow. Confirm the desired payment provider before adding one.

Use 1–6 Google Drive file-sharing links per prompt and enable “Anyone with the link”. Lazy iframe previews request media directly from Google, with an original-link fallback. No media upload, proxy or image optimization runs on the website. Google Drive access restrictions and bandwidth limits still apply.

Verification after applying the migration:

1. Register a contributor and confirm no student profile/enrollment is created; pending contributors cannot submit.
2. Allow submissions in admin; submit a prompt with Drive media and variables. It must stay hidden until approved.
3. Approve; verify guest search, variables, copying and image/video preview. Edit as contributor and verify it becomes pending again.
4. Enable direct publishing and verify the next submission is public; revoke and verify submission is denied.
5. Publish a paid prompt with an external link; confirm its template is absent from public HTML/RSC responses and only the purchase link is exposed.
6. Use a second contributor to confirm they cannot edit another contributor’s prompt. Confirm non-admin sessions cannot invoke admin actions and browser database clients cannot read the module tables.

Excel student submissions: the importer selects a populated sheet when Prompts is empty, and maps OutPut Image 01 / OutPut Image 02 Optional to Drive URLs. Timestamp and old import-status/error columns are ignored. Admins can correct every row in the preview, including unmapped or missing fields, and validate edited submissions before importing. Invalid rows remain visible with their original Excel row numbers and block the batch. Preview edits are temporary until import; remapping or selecting another file resets them. Saved prompts remain editable under Prompts > Edit prompt. Contributor and server validation remain strict.

Apply `supabase/migrations/20260905010000_optional_prompt_purchase_url.sql` before deploying the optional purchase URL change. This removes the paid-price/link dependency in the database while checking HTTPS for nonempty links. Prompt templates still require at least 20 characters.

Admin publishing: Excel import shows Save for review and Save & Publish next to the file-selection workflow. Both validate the latest preview edits before an atomic save. Save for review uses pending status; Save & Publish uses approved status and refreshes /prompts, with a public-library link after success. Buttons stay visible but disabled until rows are loaded. Existing prompt editors also have Save & Publish, which overrides the selected status and updates the same record. Public queries include approved prompts only; failed saves do not report publication.

Prompt submission form: share /prompts/submit with students. This public page embeds the existing Google Form in the website layout. Admin > Forms > Prompt Submission Form provides the copyable student link; Share your prompts in the public library and the Excel admin sharing panel point to the same route. This does not automatically sync Google Form responses into the database: import the response workbook and review/publish as before. The form currently requests Google sign-in/cookie access, so the public page includes an Open Google Form fallback above the embed. The existing contributor portal remains available at /prompts/contribute.

Excel preview editors show up to six Google Drive image/video previews beneath their links, updating when links change. Files must be shared with Anyone with the link. Preview frames are lazy-loaded and arbitrary URLs are not embedded.
